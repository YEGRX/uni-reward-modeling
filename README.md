# LatentAtlas：让不同 VAE 复用同一个潜空间奖励模型

**我们研究：能否只用少量同图配对，训练一个小接口，让不同 VAE 复用一个已经训练好的 Reward Model，同时保持这个奖励模型的权重不变？** 进一步希望，这种接入既能保留原来的评分判断，也有实际的成本优势。

本页按研究思路说明背景、方法和关键实验，更新至 **2026-10-21**。

<a id="motivation"></a>
## 一、为什么要做：已有潜空间奖励模型，换一个 VAE 后怎样继续使用？

### 1. 真正的使用场景

生成模型通常先在一份压缩表示中生成内容，最后再还原成图片。这份压缩表示叫 **latent**；把图片压缩和还原的模块是编码器和解码器，VAE是其中一类。潜空间奖励模型（Latent Reward Model，LRM）直接读取这些表示，判断候选内容的好坏，可用于候选选择或生成优化。

问题在于：**不同 VAE 对同一张图片的表示方式不同。一个奖励模型学会读取某种表示，不代表它能直接读懂另一种表示。** 我们关心不同 VAE 及相关图像自动编码器之间的接入，FLUX、Cosmos和DC-AE是已使用的具体来源，并非问题的全部范围。严格说，实验中的Cosmos CI8x8是连续自动编码器（AE），不是KL-VAE。

已有完整解决路径：把源latent还原成图片，再用奖励模型对应的VAE重新编码，然后评分。

```text
源latent → 源解码器 → 图片 → 奖励模型的参考编码器 → 已有Reward Model
```

这样能够评分，但会增加编解码步骤。对于已经拿到源latent、需要反复评价的使用者，值得研究能否用一个便宜的转换接口替代中间步骤。若手里本来就是RGB图片，直接用参考编码器评分即可。

因此，本项目要回答的是：**换用不同 VAE 时，怎样可靠、经济地复用已有奖励能力，并尽量保留在latent中评价的效率优势？** 少量配对数据、编码缓存、接口训练和搜索也有成本，需要与运行时收益一起计算。

### 2. 这个需求在已有研究中出现过吗？

下表引用原论文的两个评价：GenEval检查生成图是否满足文本中的对象、数量、位置等要求；PickScore是另一个预测图片偏好的奖励模型。它们的数值属于原论文，不是本项目的新实验。

| 已有工作 | 原文提供了什么证据 | 对我们的意义 |
| --- | --- | --- |
| [LRM/LPO，§4.3、Table 4](https://arxiv.org/html/2502.01051v5) | 使用SD1.5版LRM优化SDXL时，GenEval从49.40降至40.85、PickScore从21.65降至20.82；作者归因为不同VAE的表示分布不匹配 | 已有研究实际遇到过跨VAE复用障碍；该比较同时更换生成器，不是只替换VAE的因果实验 |
| [DiNa，附录C.3](https://arxiv.org/html/2602.11146v2) | 分别在多个骨干上训练DiNa，与复用一个已训练模型是两回事；SD3.5-M到L的复用在兼容潜空间内完成 | “有FLUX版本的DiNa”不等于原SD3.5版本可以直接接入任意VAE |
| [PRISM，§4.5](https://arxiv.org/html/2606.20310v1#S4.SS5) | 明确指出不同VAE需解码再重编码，并将空间对齐和跨模型接口列为未来方向 | 支持接入需求，也说明“加一个adapter”这个方向已有讨论；它是视频工作，其成本不能直接移作我们的图像加速结果 |

这些文献支持问题的实际存在。LatentAtlas的解决效果和成本收益，需要由自己的实验回答。

<a id="idea"></a>
## 二、我们的 Idea：用同一批图片做对照，学习一小段“翻译”

### 1. 为什么想到 Anchor？

可以把两个VAE理解成两种记录图片的方式：同一只猫在两种表示中坐标不同，但描述的是同一个内容。如果拿同一批猫、车、风景分别交给两个编码器，就能得到一批一一对应的样本。

我们的最初直觉是：**相似图片在两个空间里，可能保留某些可学习的关系。** 比如，一批相似图片在一个空间中相邻，在另一个空间中也可能形成相应的区域。这是学习转换的出发点；编码器的压缩方式不同，距离和相对位置是否保留，要通过实验检查。

这里的 **Anchor（锚点）**，就是同一张图片在两个空间中的对应表示。它提供“这两份latent表示同一张图”的监督。

### 2. Projector和REC做什么？

**Projector就是翻译接口。** 把源VAE的latent交给它，希望输出尽量接近参考VAE对同一张图片的编码。我们用一个小型卷积网络实现这种转换，项目中这套接口记作 **REC**；主比较中的版本约有3.9万个参数。

```text
                       ┌→ 源编码器 → 源latent → REC → 预测的参考latent
同一张训练图片 ────────┤                                  ↕ 比较差距
                       └→ 参考编码器 ───────────→ 实际的参考latent
```

学习时只调整REC，让上下两份参考表示更接近。**源编码器、参考编码器和已有DiNa都不更新；接口训练不使用奖励分数或偏好标签。** 典型设置是64张图片用于拟合，另64张用于挑选接口，评价再用其他图片。因此适配用到的是64＋64张配对图，不能把总配对成本写成只有64张。

这一阶段用的是完整图片编码得到、不额外叠加采样噪声的表示，称为 **Clean latent**。后文的 **Noisy State** 则是生成还没完成、仍带噪声的真实中间状态。

这里选用的下游奖励模型是 **DiNa**，参考空间是SD3.5的VAE表示。SD3.5本身是生成模型，VAE是它的组成部分。

### 3. 学好接口以后怎么用？

对已有源latent，期望使用：

```text
源latent → REC → 参考空间中的latent → 同一个冻结的DiNa → 分数
```

我们想保留的是DiNa已有的判断能力。“冻结”表示不修改其权重；输入发生了变化，判断仍可能变化，所以必须实际比较评分和排序。

早期设想是建立统一的“latent的latent”。同图配对接口在已有实验中显示出可行性后，我们先聚焦于更具体的已有模型复用问题。目前REC直接学习源空间到参考空间的转换，没有建立通用的中间空间。

<a id="experiments"></a>
## 三、实验：Anchor有用吗，评分能保留吗，离真实使用还有多远？

下面按问题排列关键实验。原编号保留在来源链接中；完整尝试、失败与执行记录见[实验档案](docs/experiments/index.md)和[近期详细记录](docs/experiments/recent/README.md)。各轮输入、训练和评价设置有所不同，结果在各自实验内比较。

### 3.1 Anchor实验：同一张图片的正确对应，真的有帮助吗？

**为什么做：**先检查接口学到的是否依赖正确的图片对应关系，而不只是“加了一个网络”。

**用了什么、怎么做：**在Cosmos连续AE到DiNa参考空间的实验中，用64张拟合图和64张选模图，比较三种情况：正确配对训练、把对应关系固定打乱后训练、保留未训练的接口。正确与打乱组使用相同初始网络、训练样本顺序和各1000次更新；按各自选模图的表示误差选择保存的模型版本。评价用开发集28组、1008对图片，DiNa保持不变。

先区分两个指标：

- **原生排序一致率（Native Agreement）：**参考路径认为A比B好，转换路径是否也这样判断？越高，表示保留原DiNa判断越多。比如100次有效比较中约95次同向，就约为95%。本轮排除参考路径的精确平局，转换路径平局计半分。
- **人类偏好准确率（Preference Accuracy）：**模型选出的图片与数据集中人类选择一致的比例。它与上一项回答不同的问题：原DiNa的判断本身也可能与人类不同。

**结果：**

| 接入方式 | 与原DiNa排序一致 | 与数据中人类选择一致 |
| --- | ---: | ---: |
| 未训练接口 | 59.677% | 44.618% |
| 打乱图片对应后训练 | 59.427% | 49.082% |
| 正确同图配对训练REC | **93.411%** | **72.619%** |
| 原生参考路径 | 100%（与自身比较） | 72.817% |

**说明什么：**正确配对显著改善了这一轮的功能保持，说明同图Anchor提供了有效监督。这里打乱的是图片对应关系，未训练对照也仍经过相同结构的接口。该结果验证一种来源和固定配方，不能直接推广成任意VAE都能接入。

[实验说明](docs/experiments/latentatlas-dina-unseen-encoder-fixed-recipe-portability.md) · [最终原报告及区间](docs/reports/latentatlas-dina-unseen-encoder-fixed-recipe-portability-final.txt)

**Anchor数量也做过比较。** 另一轮DC-AE实验使用该来源既定的较大转换网络（约89万参数），固定其结构和2000次更新，将拟合图片从64张增加到256张，另64张验证图不变；在与旧接口开发组不重叠的56组、2016对上评价。这里比较同一网络的数据量变化，与后面的REC结构比较分开。

| 拟合图片数 | 与完整解码—参考重编码路径的排序一致率 | 人类偏好准确率 | 表示误差：NMSE，越低越好 |
| --- | ---: | ---: | ---: |
| 64 | 85.8771% | 68.5392% | .296255 |
| 256 | **88.6930%** | **69.9529%** | **.210021** |

**NMSE怎么理解：**先计算预测表示与目标表示的数值差，再用目标表示的变化尺度归一化，便于比较误差大小；0表示表示完全相同。表示更接近，不自动保证排序也更接近，所以两种结果一起报告。

这次增加配对图片后，表示、排序和人类准确率都改善，但尚未达到该轮近原生要求。这是一次固定图片扩展和初始化；56组所在来源池此前也用于项目资格检查，不能当作完全独立的新总体确认。

[数量实验和最终报告入口](docs/experiments/latentatlas-dina-dcae-strong-anchor64-vs256-fixed2k-newgroups.md)

### 3.2 DiNa评分实验：REC转换后，原来的好坏排序还在吗？

**为什么做：**学出了相近坐标后，还要检查同一个DiNa是否保留了原来的判断。

**用了什么、怎么做：**先用64张同图配对拟合REC，用另64张选模。对其他评价图片，让同一张图走两条路，然后在相同文本和参考噪声设置下比较DiNa的结果：

```text
原生路径：图片 → SD3.5参考编码器 ───────────→ DiNa
转换路径：图片 → 源编码器 → REC ──────────→ 同一个DiNa
```

该轮评价是开发集28组、252张图、1008个图片对，使用四份固定参考噪声重复评分；两来源使用同一批评价图。重复噪声不是额外的独立图片。DiNa的clean评分入口会按固定设置构造带噪输入，这与直接读取源生成器的真实中间状态不同。

**结果：**

| 来源 | REC与原DiNa排序一致率 |
| --- | ---: |
| FLUX VAE | **94.7237%** |
| Cosmos连续AE | **94.6362%** |

原本4032个“图片对×参考噪声”比较中，参考路径有33个精确平局，因此一致率按3999个有效比较计算。这些比较按28组关联，不能当作3999个独立样本。

**说明什么：**在这两种来源的Clean图片编码实验中，少量配对学到的REC保留了大部分原DiNa排序。这就是“约95%”的具体含义。它衡量原判断的恢复，不表示95%的图片得到人类认可，也不直接代表真实Noisy状态可用。

### 3.3 Baseline（对照方法）比较：简单方法是否已经足够？

**为什么做：**正确配对有效，并不说明必须采用REC。需要比较已有的简单转换和相近方法。

**用了什么、怎么做：**在上面的Clean评价中，各方法使用同样的64张拟合图和64张选模图；根据表示误差选模型，再用冻结DiNa评价，不根据奖励分数挑选接口。神经方法给予相同更新与选模搜索机会；不同结构的实际计算量仍然不同。

| 方法 | 用通俗的话说，它做什么 |
| --- | --- |
| 空间仿射映射（Affine） | 用固定的加权组合和偏置换算表示，也允许使用邻近位置的信息；是需要认真比较的简单方法 |
| SD-Latent-Interposer：表示误差训练版 | 使用已有开源转换网络的结构，用本实验同图配对学习转换 |
| SD-Latent-Interposer：双向训练版 | 除了正向转换，还要求转回源空间后尽量恢复原表示；也称cycle版本 |
| REC | 本项目约3.9万参数的小卷积接口，用同图参考表示监督 |
| A2 | 项目中另一种小卷积接口，检验更换映射结构是否带来收益 |

除了排序一致率，还看**评分差误差（margin MSE）**：假设原路径给两图8分和6分，差是2；转换后给10分和9分，差是1。虽然两边都选第一张，但对“好多少”的判断不同。对所有图片对的分差误差平方取平均，就是这里的MSE；越低越好。这个例子只解释指标，不是实测分数。

**结果：**

| 方法 | FLUX排序一致率↑ | FLUX评分差误差↓ | Cosmos排序一致率↑ | Cosmos评分差误差↓ |
| --- | ---: | ---: | ---: | ---: |
| 空间仿射映射 | 91.5854% | .472092 | 90.0850% | .470821 |
| Interposer：表示误差训练版 | 90.5351% | 1.072784 | 92.2731% | .296914 |
| Interposer：双向训练版 | 86.5716% | 1.844546 | 92.6732% | .349111 |
| REC | **94.7237%** | **.298031** | 94.6362% | **.147559** |
| A2 | 92.8607% | .315073 | **94.8737%** | .156197 |

**说明什么：**

- 相比所选空间仿射映射，REC在两个来源上的排序与评分差均有改善，原报告的统计区间也支持该结论。
- 相比两种Interposer适配版，FLUX上的两项改善有支持；Cosmos上评分差误差更低，但排序改善尚未分出可靠高下。
- REC与A2尚未分出可靠高下。比较中使用的Interposer是本数据和训练设置下的适配版，不是其原发布大数据训练结果的完整复现。

这里“尚未分出可靠高下”，指考虑组间变化和多项比较后，差异区间仍覆盖0；不能只凭表中略高的平均数宣布获胜。完整区间和训练设置见[FLUX报告](docs/experiments/recent/reports/d73-flux.md)、[Cosmos报告](docs/experiments/recent/reports/d73-cosmos.md)。

**简单方法已经足够的例子也存在。** 在另一轮真实FLUX终态实验中，输入不是“把已有图重新编码”得到的latent，而是生成器实际产生的终态latent。用4条历史提示词、每条2个候选，共8图，比较REC、空间仿射和完整解码—参考重编码的DiNa结果。每候选使用两份参考噪声，平均后在两张图中选一张：

| 方法 | 与完整参考路径选中同一张图 |
| --- | ---: |
| REC直接转换终态latent | 4/4条提示词 |
| 空间仿射直接转换终态latent | 4/4条提示词 |

这一轮里，普通仿射已经保留全部4次选择，REC没有显示额外的选图收益。它是一个小样本终态实验，与前面的开发集比较分别解释。

[真实终态实验报告](docs/experiments/recent/reports/lrm-r1-results.md) · [原始评分表](docs/experiments/recent/tables/lrm-r1-four-path-results.csv)

### 3.4 离真实使用还差什么？真实Noisy实验得到了什么？

#### 第一，前面的Clean实验与生成中途评价还有距离

Clean指没有叠加采样噪声的图片表示；Noisy State指生成过程中仍带噪声的状态。如果已经有完整图片，直接使用像素奖励模型或参考编码路径通常就能评价。latent奖励的一项重要用途，是生成尚未结束时就作判断，帮助选择值得继续生成的候选。

所以需要进一步检查：**用完整图片学到的接口，能不能在真实生成中途继续工作？** 人工给完整表示加噪，可以做受控检查；生成器实际走到的中间状态，还要单独验证。

#### 第二，真实生成中途：直接转换，还是先预测清晰状态？

**用了什么、怎么做：**最近一次实验取2条历史提示词、4条真实FLUX生成轨迹，在28步采样的k23和k26两个时点保留状态，共8个真实Noisy状态。REC、空间仿射和DiNa全部沿用已有权重，本轮不训练新接口。

比较三条接入路线，并与完整参考路径比较：

```text
完整参考：当步清晰预测 → 源解码器 → 图片 → 参考编码器 → DiNa
预测再转换：当步清晰预测 → REC ──────────────────────→ DiNa
直接转换：真实带噪状态 → REC或空间仿射 ──────────────→ DiNa
```

**“当步清晰预测”是什么？** 生成器在当前这一步估计“如果去掉噪声，图片表示大概是什么”。它不是提前读取最终结果，使用当步去噪预测的计算也要计入成本。时间位置和噪声强度需要分别匹配；真实带噪输入也不能被误当成Clean而再加一遍噪声。完整参考和预测再转换各用两份固定参考噪声，直接转换路径不再额外加噪。

**结果：**下表看每条提示词的两个候选，是否选中与完整当步参考相同的候选；本轮这些参考选择也与完整终态参考同向。

| 路线 | k23时点 | k26时点 |
| --- | --- | --- |
| 先预测清晰状态，再用REC转换 | **2/2同选** | **2/2同选** |
| 带噪状态直接用REC转换 | 2/2同选 | **1/2同选，另一条反向** |
| 带噪状态直接用空间仿射转换 | 1条同选、1条平局 | 1/2同选，另一条反向 |

**说明什么：**本轮支持继续考察“先预测清晰状态，再复用Clean接口”这条路线；直接把带噪状态交给原接口，在不同时间点表现不稳定。预测再转换保留了本轮选择，但并非所有数值误差都最小：k23的评分差MSE，直接REC为.06640625，预测再转换为.166015625。实验只有2条历史提示词，两个截面也都接近采样后段，尚不能估计一般成功率或早期选择收益。

[真实Noisy完整报告](docs/experiments/recent/reports/lrm-n1-results.md) · [输入与时间设置](docs/experiments/recent/reports/lrm-n1-contract.md) · [逐状态原表](docs/experiments/recent/tables/lrm-n1-per-state-comparison.csv)

#### 第三，保留DiNa判断以后，还要确认这个判断是否值得使用

对前述4条提示词、8张真实终态图，读取已有DiNa与PickScore结果，两模型只在 **1/4** 条提示词上选中同一张图。PickScore是另一个奖励模型，不是人类答案；这八图没有对应的人类偏好标注，所以目前无法据此判定谁正确。

这说明下一步需要目标生成内容上的人类偏好依据。即使接口完全复现DiNa，也仍要分别确认原Reward在这个使用场景中的可靠性。

[Reward有效性分析](docs/experiments/recent/reports/lrm-r2-validity.md) · [四组原始比较表](docs/experiments/recent/tables/lrm-r2-reward-comparison.csv)

**如果把不同来源的候选放在一起选，分数标尺还要检查。** 旧开发集混合路径实验发现，相比各自内部比较，额外排序失配为3.5696个百分点；用两折开发数据估计简单分数偏移后降至.8252个百分点。“百分点”表示两个百分比直接相减。该校准使用了额外奖励信息，尚未在独立新组上确认；本轮Noisy实验也没有验证混合来源选图。

[混合评分与校准记录](docs/experiments/recent/notes/latentatlas-cross-encoder-reward-consistency-dev28.md)

#### 当前得到什么、还缺什么？

| 已得到的证据 | 接下来需要回答 |
| --- | --- |
| 正确同图Anchor提供有效监督；特定扩展实验中更多配对带来改善 | 更换独立图片和来源后，收益是否保持，最低适配成本是多少？ |
| Clean接入中REC保留了约95%的原排序，并有匹配基线比较 | 在新内容和源生成器原生latent上，功能损失是否可接受？ |
| 小样本终态上普通仿射已足够；真实Noisy中预测再转换保留本轮选择 | 哪些情况下需要REC，能否在更早的真实状态提供有用选择？ |
| 已有原始分数、失败与对照记录 | 是否符合人类偏好，是否真正省下包含去噪、编解码和DiNa在内的完整成本？ |

**目前最明确的研究主线是：让不同VAE复用已有LRM时，保留可靠的奖励行为，并核实适配和运行的实际收益。** 高排序一致率是其中一项基础证据；奖励反传的梯度可靠性和生成优化收益，还需要各自的实验。

## 四、主要参考文献：它们做了什么，与我们有什么关系？

下面保留与主线最直接的论文和实现。完整作者、版本、书目和其他相关论文见 [Related Work](docs/related_work/README.md)、[BibTeX](docs/related_work/references.bib)及[原文核查记录](docs/related_work/source_audit.md)。

### 1. LRM/LPO：Diffusion Model as a Noise-Aware Latent Reward Model for Step-Level Preference Optimization

[论文v5（2025）](https://arxiv.org/html/2502.01051v5) · [官方代码](https://github.com/Kwai-Kolors/LPO)

**这篇工作做了什么：**把扩散模型的一部分训练成能读取带噪latent的奖励模型，在生成的每一步挑选候选并优化生成器。它用偏好数据训练LRM，并实际检验了跨生成器使用；不同VAE的SDXL比较出现部分主要指标下降。

**与我们的联系和相同点：**都希望直接在latent中获得可用于选择的奖励反馈；它提供了跨VAE障碍的直接实验依据。

**不同点：**它研究奖励模型训练与逐步生成优化；我们先固定一个已有LRM，只用同图坐标配对学习输入转换。我们的接口实验尚未完成它所评价的生成优化任务。

### 2. DiNa-LRM：Beyond VLM-Based Rewards: Diffusion-Native Latent Reward Modeling

[正式论文（ICML 2026）](https://proceedings.mlr.press/v306/liu26fh.html) · [所读v2](https://arxiv.org/html/2602.11146v2) · [官方代码](https://github.com/HKUST-C4G/diffusion-rm)

**这篇工作做了什么：**利用扩散模型主体网络对不同噪声的处理能力，训练带时间条件的奖励读出，并用于偏好评价和生成对齐。底层读取noisy latent、时间和文本；给Clean表示评分时，封装会构造参考噪声。

**与我们的联系和相同点：**它是实际复用的下游奖励模型，也是我们希望保留的评分能力来源。

**不同点：**原工作训练奖励能力；我们不更新已经训练好的完整DiNa。原文的多骨干版本和共享空间迁移，并未解决同一份权重对任意不兼容VAE的直接复用。

### 3. PRISM：Through the PRISM: Preference Representation in Intermediate States of Video Diffusion Models

[论文v1（2026），重点§4.5](https://arxiv.org/html/2606.20310v1)

**这篇工作做了什么：**在冻结的视频扩散主体网络上学习奖励读出，直接评价带噪视频表示，并用于提前筛选候选。

**与我们的联系和相同点：**同样关注latent内部评价的实际用途。作者明确指出不同VAE需要像素转换，并提出空间对齐和跨模型接口这一未来方向，为需求提供了直接表述。

**不同点：**它研究视频奖励建模，我们当前验证图像模型的固定奖励接入；其效率结果不能当作本项目收益。“用adapter跨空间接入”这个大方向也已经存在。

### 4. SD-Latent-Interposer（开源项目）

[官方仓库](https://github.com/city96/SD-Latent-Interposer)

**这个项目做了什么：**用配对latent训练卷积转换网络，把一种VAE表示转换成另一种表示，供后续生成流程使用。

**与我们的联系和相同点：**同图配对、小卷积和跨VAE转换，与REC训练非常接近，是需要直接比较的已有实现。

**不同点：**我们重点检查同一个冻结Reward的分数与排序是否保持；转换表示只是手段。前面的对照使用该实现的结构和明确的本实验适配设置，不能凭用途差异就认定方法新颖。

### 5. Revisiting Model Stitching in the Foundation Model Era

[CVPR 2026正式页](https://openaccess.thecvf.com/content/CVPR2026/html/Mai_Revisiting_Model_Stitching_In_the_Foundation_Model_Era_CVPR_2026_paper.html) · [所读v3](https://arxiv.org/html/2603.12433v3)

**这篇工作做了什么：**固定不同视觉模型的前后部分，只训练连接层，检查组合后能否分类或分割。它比较在连接处匹配表示、匹配最终特征，以及继续用任务标签训练连接层。

**与我们的联系和相同点：**都用小接口连接已有模型，并检查后续功能。我们目前用配对latent训练接口，与它的连接处特征匹配思路接近。

**不同点：**它拼接视觉模型的中间层并研究互补能力；我们接入完整固定DiNa的输入。它也提醒我们：连接处数值接近，不保证最后判断相同；最终特征或任务监督读取的信息比纯坐标配对更多。

### 6. Latent Space Translation via Semantic Alignment

[NeurIPS 2023正式页](https://papers.neurips.cc/paper_files/paper/2023/hash/ad5fa03c906ca15905144ca3fbf2a768-Abstract-Conference.html) · [所读v2](https://arxiv.org/html/2311.00664v2)

**这篇工作做了什么：**给不同编码器输入对应内容，利用这些配对表示求出空间之间的变换，再接入原来的分类器或解码器。它比较线性、正交和仿射等转换；其中一些可直接用代数方法求解。

**与我们的联系和相同点：**这是同图Anchor和表示翻译最接近的前作之一，都利用对应样本连接已有模型。

**不同点：**它研究多架构、跨模态和重建等一般任务；我们具体检验完整冻结LRM在异构输入下的奖励行为与成本。这个应用问题需要自己的证据，配对翻译本身已有先例。

### 7. Stitched Value Model for Diffusion Alignment（StitchVM）

[论文v1（2026预印本）](https://arxiv.org/html/2605.19804v1) · [官方代码](https://github.com/prs-eth/StitchVM)

**这篇工作做了什么：**让冻结扩散前缀读取带噪latent，再通过接口接到图像奖励模型的后半部分。选择连接位置后，训练接口与学生奖励后缀，利用原奖励模型提供教师信息，并测试生成引导和训练对齐。

**与我们的联系和相同点：**都想复用已有奖励知识，扩展到noisy输入。它已研究noisy-latent stitching，也是我们真实Noisy方向的重要竞争路线。

**不同点：**它会训练被拼接的奖励后缀，并使用奖励教师信息；我们希望完整DiNa保持不变，接口只用坐标配对学习。这是监督和训练权限的区别，实际优劣还需匹配用途与成本比较。当前公开训练配方与论文不同，复现时需分开。

### 8. Latent Space Translation via Inverse Relative Projection

[论文v1（2024）](https://arxiv.org/html/2406.15057v1)

**这篇工作做了什么：**先用“一个样本与各个Anchor的关系”描述它，再借助目标空间的Anchor把它还原成目标坐标。相对表示成为不同空间之间的中转站，方法依赖相应的几何与稳定性条件。

**与我们的联系和相同点：**同样依靠对应样本寻找空间联系，和早期“latent的latent”设想较接近。

**不同点：**当前REC直接学习源到参考空间的转换，没有经过共享相对空间。该路线是理解和比较空间翻译的参照，尚未在本项目中验证其冻结Reward表现。

**这些文献共同说明：跨空间翻译、冻结模型拼接、noisy奖励接入都有前作。** 本项目需要用实际结果说明，在少量配对且不更新已有奖励模型的条件下，能保留多少有用判断，适配和运行代价是否值得。进一步的线性映射、生成模型拼接及去噪理论分析保留在 [Related Work](docs/related_work/README.md)。
