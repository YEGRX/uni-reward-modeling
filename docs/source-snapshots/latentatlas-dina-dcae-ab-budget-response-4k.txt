## 2. Purpose

在旧四格实验A=P0/T0、B=P0/T1各自1000步完整状态上继续同一原12000步学习率日程，先统一到2000步。用预先冻结的全VAL自身目标坐标loss门决定是否把两臂都继续到4000步。随后在固定1008对、28关联组、4流上评价选定终点。不能把阶段门控解释为数学收敛证明。

## 4. Dataset / Input

旧64 FIT/64 VAL Anchor，T0/T1与共同W0；旧A、B、Native、G逐行分数现已通过远端CPU对旧F1最终封存链和1008行来源身份核验，可作为新评分入口的参照；新A/B评分入口尚未运行。旧A/B各自1000步checkpoint由原不可变`verify_fit`在远端CPU独立通过；三份1K loss CSV逐字段与原封存状态一致。128对stream0探针按身份哈希冻结，但门控seal之前不得评分。

## 5. Parameters and Gate

A自身目标用VAL_T0，B用VAL_T1。在1000、1250、1500、1750、2000步离线做FIT/VAL×T0/T1全Anchor诊断；若任一臂同时满足1000→2000相对下降≥3%与1500→2000相对下降≥1%，两臂都继续到4000。否则两臂都停止在2000。决策必须在读取任何新增Reward结果前封存。阈值不根据结果更改。

## 7. Problems and Fixes

原训练入口限制到1000步；新run独立扩展采样器和学习率取值范围，不改旧封存代码。阶段一全Anchor诊断、续训更新入口、追加式检查点/恢复链已实现；连同原适配器和纯门控组件此前15项远端CPU测试通过；另有恢复组件18项及新资源账本/进程守护12项远端CPU测试通过。新run Reward/backbone 计数适配器连同旧封装回归共41项远端CPU测试通过，实际模型调用尚未运行。账本已在代码层限制2K门控前Reward和2001+更新，但只在私有CPU测试锁下验证守护逻辑，尚无生产GPU进程、真实恢复一致性或预算准入。阶段一检查点API仍拒绝2500步及以后；阶段二使用独立的GO绑定与追加式状态链，避免决策封存前误入Phase II。正式更新在两个250步检查点之间若进程失败，现账本的已应用计数与回滚到旧检查点之间存在恢复冲突；新账本/检查点恢复桥已实现显式保留失败费用与被放弃更新的证明链，并通过远端CPU组件测试；实际CUDA失败重启与生产入口尚未核验。

阶段化资源核算又发现：既有技术DiNa已用69/128，每个新GPU进程必须真实准入23。GO路径若把阶段一、阶段二、评价分成三个进程，将达138并越过上限；当前设计为同一训练进程完成两臂2K、独立CPU复核并封存Reward-blind门控、若GO则继续两臂4K，最后另开默认backend评价进程，理想无故障总计115。阶段一双臂共用进程的有界入口已提交并在远端CPU重点测试4项通过；该入口本身仍会在门控前退出，**禁止当作完整正式链启动**。阶段二全状态的追加式发布、独立逐文件回放及GO资格约束的训练内核已通过远端CPU组件测试。同一训练会话内的双臂2K、独立CPU门控封存和条件性双臂4K调用链现已接线，远端CPU相关84项回归通过；尚无不可变完整发布、真实CUDA续训、评价或最终回放，正式更新与新增Reward评分仍为0。一次额外新进程会超过理想路径剩余13个技术条件，必须按固定预算停下处理。

当前进程受锁评估会话与生产worker已接线，远端CPU相关9项测试通过；实际新进程CUDA评分、不可变完整发布、独立双回放仍未发生，正式训练/新Reward均为0。证据：`raw/experiments/latentatlas/dina-dcae-ab-budget-response-2026-09-27/evaluation-worker-component-20260927T1910/SELECTED_EVALUATION_WORKER_REMOTE_CPU_TEST.json`。
