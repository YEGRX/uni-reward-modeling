# LatentAtlas U5-PB1 Predictive-U Capacity and Spatial Topology Localization

## 1. Date

2026-08-26

## 2. Purpose

在复用 P4096、known-VAE、reward-free 的 development protocol 中，承接 [[latentatlas-u5pb0-target-free-predictive-bottleneck]]，定位 PB0 的 compact predictive-U 缺口主要来自：

1. token capacity；
2. decoder 的显式 Spatial Write；
3. U 内部的 Spatial Read / spatial organization；
4. 或当前冻结 bottleneck family 仍不足。

Case B 冻结为“原 decoder 没有合格的显式 spatial Write”。本实验只做 architecture localization，不读取 Reward、Reward Head、RGB、H/H-bar，也不评估 unseen VAE。

## 5. Parameters

强制矩阵：`Q16-R/Q32/Q64/Q128/Q64-W/S64-W`。当 validation 上 `A_read>0.20` 且 `S64-W deficit>0.05` 时才运行 optional `SG80-W`；本次 trigger=`true`，因此共训练 7 个模型。

共同配置：seed=`20260826`、batch=`32`、每模型 `12,000` updates、24 次 validation、Apple MPS BF16、同一 initialization registry 和 batch schedule。所有 7 臂 `optimization_adequate=true`。

冻结主比较：

- Capacity：`Q16-R→Q32→Q64→Q128`。
- Write：`Q64→Q64-W`，注册量 `A_write`。
- Read：`Q64-W→S64-W`，注册量 `A_read`。
- Hybrid：`S64-W→SG80-W`，只作 modifier。

## 8. Analysis

本结果支持：在当前冻结 predictive-U family 内，增加容量有帮助但不充分；单独添加 Spatial Write 无益；在相同 Write 下让 U 具有明确 spatial organization 带来大幅、稳定改善。因此 headline 是 `READ_SPATIAL_TOPOLOGY_LIMITED`。

它不支持把 `S64-W` 晋升为 canonical U。`S64-W` 虽是最佳 U 候选，仍比 B3 留下约 31.4% registered compact deficit。结果也不证明 fresh-holdout、unseen-VAE、Reward/Flow/Diffusion transfer、多 seed 稳定性或全局最优架构。

后续 [[latentatlas-u5pb1r1-residual-information-localization]] 已对这部分 deficit 做 frozen forward-only 诊断。Validation 显示 mid+high frequency 占比为 `0.827552 [0.820041,0.834740]`，但 channel/patch concentration 均为负、source evidence 不确定，故分类为 `RESIDUAL_LOCALIZATION_INCONCLUSIVE`。其 Evaluation authority 在任何 forward 前因 hash-schema mismatch 停止并已消费；该后续 attempt 未 `FINALIZED/VERIFIED`，不改变本页已封存的 PB1 结果。

## 9. Problems

1. 初始 PILOT 在 prepare 时因 `torch.__version__` 的 `TorchVersion` 字符串子类不满足 strict JSON exact type 而停止；未训练、未访问 validation/evaluation。修复为原生 `str` 后开新 identity。
2. `REPLAY01` 在 durable evaluation access 后发现 Apple MPS fused `BF16/FP32→CPU float64` 可把 finite 输出转成 NaN；该 attempt 已消费并独立归档，没有续跑或复用。
3. validation-only 复现得到 direct conversion=`182 NaN`，安全两段转换=`0 nonfinite`；修复覆盖 prediction、U encode/decode、train mean、target、Stage-0 和 aggregate，随后以 `REPLAY02` 从头训练和评价。
4. 第一次 verifier CLI 使用相对 run path，导致路径重复拼接；未写 receipt。绝对路径严格重放两次均得到同一 terminal inventory SHA。

## 10. Next Steps

冻结建议是 `DO_NOT_PROMOTE_AND_RESOLVE_REGISTERED_GRAY_ZONES`。后续 PB1R1 已定位 residual，但 Validation 分类为 `RESIDUAL_LOCALIZATION_INCONCLUSIVE / DO_NOT_SELECT_NEW_ARCHITECTURE`；Q64-W 的 sealed registered noncollapse failure 仍是 effective rank=`15.271196` 未超过 `16.0`。

当前不自动启动 PB2、Reward transfer、新 seed/fold 或 canonical-U promotion。若要补 PB1R1 的 secondary Evaluation，只能另冻 corrected protocol、new run identity 与真正新的 authority，不能续跑已消费 attempt。
