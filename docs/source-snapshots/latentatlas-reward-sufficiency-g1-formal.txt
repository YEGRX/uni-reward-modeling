# LatentAtlas G1 正式 Reward-Sufficiency 实验

> [!IMPORTANT]
> 本次 formal run 已 terminal `complete / pass` 并完成 durable seal；正式机器判定是 `no / control_failure`。三个 VAE family 的 signal gates 通过，但三个 label-shuffle controls 全部失败。后验独立科学解释审计另有 `Critical=0, Important=1`：shuffle 训练只置乱 train labels，却用真实 source-validation labels 选择 checkpoint。故本结果不能称为 **Partial Reward-Sufficiency** 或 **Strong Reward-Sufficiency**。

## 1. Date

2026-08-15

## 2. Purpose

在冻结的 G0.1 数据 authority 上，检验 parameter-shared Reward Head 能否从两个 source VAE 的 Anchor-relative representations 学到人类视觉连贯性偏好，并在只做 calibration-only Anchor onboarding、不给 target labels 的第三个 VAE 上迁移。实验覆盖 SD-VAE、FLUX VAE、DC-AE 的 leave-one-VAE-out（LOO）方向、三个 Anchor seeds、三个 training seeds、global cosine / rank operators、linear / MLP heads、wrong-Anchor 与 label-shuffle controls，并以 component-clustered bootstrap 执行预注册 gate。

该页是 [[latentatlas-reward-data-preflight-g01]] 与 [[latentatlas-reward-sufficiency-g1-true-smoke]] 之后的正式实验记录。它回答冻结协议下的 bounded reward-sufficiency 问题，不等价于已经得到通用 cross-VAE canonicalization。

## 8. Analysis

### 8.1 正式科学解释

最保守、可复现的结论是：在当前冻结协议下，三种 target VAE family 都出现高于随机的 oracle / LOO signal，且 correct Anchor 相对 wrong Anchor 的 effect 为正；但 label-shuffle controls 并未回到预注册的随机带。因此实验不能把 observed signal 归因为通过了完整 controls 的 reward sufficiency，也不能据此启动或宣称 cross-VAE canonicalization 成功。

这不是“没有任何 Reward information”的证明。`no / control_failure` 的含义是：signal 条件本可达到更高分级，但必要 control 失败，因而正式结论必须停在 No。

### 8.2 后验独立科学审计：C=0 / I=1

唯一 Important finding 是 shuffle validation 的真实标签选择通道（real-label model-selection channel）：

1. `reward_capabilities.py` 的 label-shuffle assembly 只置乱 source-train sides；source-validation batches 仍使用真实 `preferred_source_side`。
2. `reward_head.py` 每个 epoch 在真实 source-validation labels 上计算 macro BT-NLL，并依此 early-stop、选择 minimum-NLL 的最早 checkpoint。
3. 冻结 design spec 同样明确规定 train labels shuffled，而 validation / test labels remain real。

因此这个 shuffle condition 不是完全切断真实标签信息的 pure null：训练梯度不看真实 train labels，但 checkpoint selection 看到了真实 source-validation labels。独立科学解释审计据此记录 **Critical=0，Important=1**。

该 finding 是 post-run independent code audit caveat；sealed `gate-summary.csv` 的 `invalid_reasons` 为空。它不能被写成 sealed run 原本自带的 invalid reason，也不能反向修改已经封存的 machine gate。

这项 finding 不表示 target-label leakage，也不是 terminal seal failure；target/source oracle 的物理打开与封存边界仍由 terminal artifacts 单独证明。它不改写机器已经输出的 `no / control_failure`，但进一步禁止将 signal-only 结果称为 Partial 或 Strong。未来若修复，应预注册不使用真实 validation labels 的 null-selection rule，并作为新实验保留独立谱系，不能覆盖本 sealed run。

## 9. Problems

- 三个 label-shuffle controls 全部失败，因此 protocol 的必要对照条件不成立。
- Shuffle condition 还存在真实 source-validation label 驱动的 checkpoint-selection channel；它削弱 pure-null 解释。
- 该审计 finding 是 post hoc（结果后）发现，不能在本 run 上临时改变 gate 规则、重选 checkpoint 或重定义 control。
- Cross-view consistency、transfer efficiency 与 signal-positive family metrics 都是支持性或诊断性结果，不能替代失败的 controls。
- Compact mirror 为知识库证据子集，不包含 opened-label、cache、model 或 score 大树；需要逐对象复核时必须回到完整 run。

## 10. Next Steps

1. 保留 `no / control_failure` 作为本次 formal G1 的不可变结论，不进行 Partial / Strong 升级。
2. 若另行批准新实验，先修订并预注册 shuffle null 的 checkpoint-selection rule，使 selection 不访问真实 validation labels。
3. 在修订 control 前，不启动 cross-VAE canonicalization、learned `U`、Latent² 或更大规模 reward-transfer 扩展。
4. 新实验必须生成新的 run identity、plan、oracle results 与 terminal seal；不得覆盖本次 durable run。
5. 当前只剩 Wiki 归档和人工复核，不需要 GPU 或远程服务器；若租用 GPU 仍在运行，可以关闭。
