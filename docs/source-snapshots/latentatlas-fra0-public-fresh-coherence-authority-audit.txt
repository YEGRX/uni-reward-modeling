# LatentAtlas FRA-0 Public Fresh Human-Coherence Authority Audit — 完整实验报告

> **报告范围**：本报告完整覆盖 2026-08-24 的 FRA-0 首次正式运行、随后独立执行的 FRA0-R provenance recovery，以及两者共同形成的科学边界。两个 sealed result 均保持不可变。
>
> **最终结论**：首次运行因公开源连接失败而以 `DATASET_PROVENANCE_FAILURE` fail closed；FRA0-R 排除该网络因素后，四个固定候选均因缺少 revision-bound side-order evidence 而被完整、结论性拒绝，最终为 `NO_SUITABLE_PUBLIC_FRESH_COHERENCE_AUTHORITY`。这表示“当前四候选在冻结证据合同下不可形成可定向 authority”，不表示数据集没有有用标签，也不是 LatentAtlas 方法的科学负结果。

## 2. Purpose

### 2.1 研究背景

LatentAtlas 的 U4-A 系列已经在历史 development cohort 上得到 reward-free 的 correct-pairing specificity 信号，但它不能回答 frozen Reward Head 在 fresh human-coherence authority 上是否仍具有功能特异性。既有 [[latentatlas-c1r-fresh-authority-audit]] 又证明，G0.1 当前快照的全部 56,074 个有有效方向的 pair 已被历史实验消费，无法再充当新的 confirmatory authority。

因此，FRA-0 的任务不是训练或评价模型，而是先回答一个权限问题：公开数据中是否存在一套来源可复现、标签语义匹配、方向可证明、与 G0.1 图像和 prompt 隔离，并可冻结为 A1/A2/A3 三个 lockbox 的 fresh human-coherence authority。

### 2.2 核心研究问题

对四个预先固定的 Rapidata 候选，依次判断：

1. 能否把数据卡、schema、全部 official Parquet inventory 和固定语义样本绑定到 immutable 40-hex revision？
2. 标注问题是否属于 `MATCHED_COHERENCE` 或 `NEAR_MATCHED_COHERENCE`？
3. `image1/image2`、原始 option 顺序和 vote encoding 的关系是否有 revision-bound 证据，从而能安全推导 Reward-positive 方向？
4. 通过方向门后，是否能证明与 G0.1 无 exact image overlap、无 pHash≤4 near duplicate，并构造 prompt-disjoint pool？
5. 通过 hygiene 后，确定性分组和哈希分配能否满足 A1/A2/A3 的最小 pair/image 数？

### 2.3 冻结终态

FRA-0 只允许三种 global terminal status：

| 终态 | 精确含义 |
|---|---|
| `FRESH_AUTHORITY_READY` | 至少一个候选完成全源审计并形成可验证的 selected pool、authority groups 和 A1/A2/A3 lockboxes。 |
| `NO_SUITABLE_PUBLIC_FRESH_COHERENCE_AUTHORITY` | 所有固定候选都获得结论性结果，但没有候选通过全部 eligibility/engineering gates。 |
| `DATASET_PROVENANCE_FAILURE` | 至少一个仍可能合格的候选因来源、下载、schema 或全源处理不完整而无法下结论；缺失证据不能被伪装成科学 rejection。 |

### 2.4 范围与禁止事项

FRA-0 仅允许 CPU、网络、本地存储、hashing、strict JSON、Pillow、PyArrow 和 pHash 等 authority infrastructure。生产入口禁止触达 VAE、latent encoding、Torch training、Reward Reader/checkpoint、C0/C1/C2/G/O/U 系列 evaluation 或任何 model-performance metric。

所以，本实验无论得到哪一种 terminal status，都不直接评价 shared latent structure、candidate `U`、Reward transfer 或 unseen-VAE onboarding。

## 5. Parameters

### 5.1 固定身份与近重复规则

- Run identity：`FRA0_PUBLIC_FRESH_COHERENCE_AUTHORITY_AUDIT`
- Candidate order：Seedream-3 → Recraft-v3 → HunyuanImage-2.1 → Flux-2-pro
- Public identity mode：`UNORDERED_PUBLIC_PAIR_IDENTITIES_V1`
- Canonical RGB：`LATENTATLAS_RGB_V1`
- EXIF policy：`LATENTATLAS_STORED_RASTER_NO_EXIF_TRANSPOSE_V1`
- pHash：`LATENTATLAS_PHASH64_DCT32_MEDIAN64_MSB_V1`
- Near-duplicate threshold：Hamming distance ≤ 4
- Prompt namespace：`LATENTATLAS_FRA0_PROMPT_NFC_STRIP_V1`
- Runtime：Pillow `12.3.0`、NumPy `2.4.6`、pHash dtype `float64`

Prompt ID 使用 Unicode NFC、仅去除首尾空白，然后对 namespace、分隔符和 UTF-8 prompt 计算 SHA-256；不做大小写折叠、内部空白改写、semantic matching 或 embedding/paraphrase matching。

### 5.2 方向合同

四个候选的数据卡问题均为：`Which image has more glitches and is more likely to be AI generated?`。因此原始较高 coherence vote 表示“更多 glitch / 更差”，进入 LatentAtlas authority 前必须按 `FRA0_COHERENCE_HIGHER_IS_WORSE_INVERSION_V1` 反转为“更少 glitch / Reward-positive”。

该反转只有在 source side 与原始 option/vote encoding 的关系被 revision-bound 证据证明后才允许执行。字段名相似、总体比例平衡、人工看图猜测或跨仓库类比均不能替代 side-order authority。

### 5.3 Pool 定义

| Pool | 冻结条件 | 权限 |
|---|---|---|
| `POOL_A` | 有效 coherence orientation，且无 exact old-image overlap | 仅诊断，不能成为最终 authority |
| `POOL_B` | `POOL_A`，且两侧均无 old-image pHash distance ≤ 4 | 可选；若选择必须披露 prompt overlap |
| `POOL_C` | `POOL_B`，且 prompt ID 不在 G0.1 prompt set 中 | 首选 authority pool |

### 5.4 Authority group 与 lockbox

保留 pair 若共享 canonical image 或 prompt，则通过 union-find 形成一个不可拆分 authority group。Group assignment 使用固定 salt `LATENTATLAS_FRA0_V1` 和 revision/group hash 的十个桶：

- bucket 0–3 → `A1_PHENOMENON_CONFIRMATION`
- bucket 4–7 → `A2_METHOD_CONFIRMATION`
- bucket 8–9 → `A3_RESERVE`

冻结最低门槛：

- A1：≥5,642 usable pairs 且 ≥723 unique images
- A2：≥5,642 usable pairs 且 ≥723 unique images
- A3：≥2,500 usable pairs

任何 group 均不得在看到计数或标签后人工移动。

### 5.5 FRA0-R 的唯一实现变化

Recovery 保持相同 config、四个 candidate revisions、语义合同与所有 selection gates，仅允许在同一 immutable revision 上对精确 `httpx.ConnectError` 做最多 5 次有限重试，退避为 `1/2/4/8` 秒。内容、schema、hash 或 provenance 校验失败仍立即 fail closed。

## 8. Analysis

### 8.1 结果证明了什么

1. FRA-0 production pipeline 能够在公开来源证明不完整时 fail closed，并把缺失证据保持为 `NA`，而不是伪造成候选 rejection。
2. Recovery 证明首次 blocker 是暂态 metadata network/provenance 问题，而不是 Flux dataset 内容已被判定不合格。
3. 在相同 immutable revisions 和相同科学协议下，四个候选都具有 near-matched coherence 语义，但都缺少足以推导 Reward orientation 的 revision-bound side-order authority。
4. 因四个候选均在 eligibility 层获得结论性拒绝，global `NO_SUITABLE_PUBLIC_FRESH_COHERENCE_AUTHORITY` 在该冻结四候选合同下成立。
5. Authority system 的 capability isolation、事件链、条件文件树、terminal seal 和无 selected-authority 状态均可独立重放。

### 8.2 结果没有证明什么

本实验不证明：

- 四个 Rapidata 数据集没有有用的 coherence labels；
- 它们的真实 option/image mapping 错误；
- 所有公开数据都不可能形成 fresh authority；
- exact/near image overlap 或 prompt overlap 的数量为零；
- pool/lockbox 一定太小；
- Anchor、Bridge、candidate `H/U`、canonical U 或 shared latent structure 不成立；
- frozen Reward Head 不能 transfer；
- unseen-VAE onboarding 或 cross-distribution generalization 失败。

这里唯一被否定的是：**在冻结的四个候选 revisions 与当时已注册的公开证据下，无法合法地把 pair vote 转成 LatentAtlas Reward-positive orientation，因此不能构造 FRA-0 authority。**

### 8.3 为什么不能“根据字段名猜方向”

如果把 `weighted_results_image1_coherence` 直接解释为 image1 的原始 option vote，需要额外假设 exporter 保持了 option order、UI 换边后恢复原序、`votedFor` 与文件列映射稳定，以及四个 revisions 使用同一生成代码。任一假设错误都会系统性翻转部分或全部 Reward labels。

FRA-0 的作用正是阻止这类来源不明的标签进入后续 confirmatory experiment。方向证据缺失是 authority blocker，不是一个可以靠肉眼 spot-check 或多数统计修复的普通数据清洗问题。

### 8.4 与项目后续进展的关系

FRA0-R 是 2026-08-24 对这四个特定候选的历史结论。2026-08-25，项目通过不同来源与不同冻结协议完成 [[latentatlas-u4b0-fresh-functional-authority-gate]]：`Rapidata/svg-benchmark` 固定 revision 最终形成 284-pair/568-image fresh authority，U4-B0 独立 verifier=`PASS`。

这项后续进展说明“公开 fresh authority 不可能获得”从来不是 FRA-0 的结论；它也不回写或推翻 FRA-0。两者可以同时成立：

- FRA-0：原四个 t2i candidates 缺少 revision-bound side-order 证据，不能授权。
- FRA-SVG0/U4-B0：另一条具有完整方向合同的公开数据路线已经成功封存 fresh authority。

当前最新研究阻点已从“有没有 fresh authority”推进到“exact frozen head/reference 在 fresh H 上是否 adequate”，而不是继续重复 FRA-0 的四候选审计。

## 9. Problems

### 9.1 首次运行的操作性问题

Hugging Face metadata 连接在 Flux shard 9 失败，使四候选共同 revision barrier 不完整。原 sealed attempt 不允许原地补跑；独立 FRA0-R 使用新 worktree、production commit 和 output root 恢复。

### 9.2 最终 authority blocker

四个固定 revision 均缺少官方 exporter/code/document 对 `option 0/1 → image1/image2` 的专门绑定。后续 FRA0-SO 第一方检索只找到了通用 SDK 与 benchmark 的 option/vote/coherence 极性说明，没有找到四个目标 revisions 的 exporter identity，因此 formal `side_order_evidence` 仍必须为 `UNPROVEN`。

### 9.3 数据规模与成本

四候选合计约 121.6 GB。方向门在 payload 前完成，避免了无权限数据的大规模下载、解码与 pHash 计算。这是协议预期的成本控制，不是实验偷跑或缺失。

### 9.4 报告解释风险

- `SEALED_PASS` 的 cross-artifact audit 表示“失败/拒绝结果自洽”，不表示 scientific authority 通过。
- `SEALED_REJECTED` 是候选在 orientation eligibility 合同下的结论，不是对数据集总体价值的评价。
- `NA` 不能改写成 0。
- `NO_SUITABLE...` 的量词范围仅为四个固定 candidates 与冻结证据合同，不是所有公开数据。

### 10.1 对 FRA-0 历史路线的停止规则

- 不在没有新 revision-bound side-order authority 的情况下原样重跑四个候选。
- 不猜测 orientation，不依据字段名或样本外观补标签。
- 若未来必须重启该路线，只接受能够绑定到具体 revision 的官方 exporter code/schema/document，并使用新的 run identity。

### 10.2 当前项目行动

FRA-SVG0/U4-B0 已通过另一条路线形成 fresh authority，因此当前无需继续修复 FRA-0。后续研究应遵循 [[latentatlas-u4b1-284-exploratory-fresh-functional-specificity]] 的边界，优先定位 frozen head/reference adequacy；任何最终 fresh confirmation 仍需新的未消费 authority，不能重复使用已经消费的 284 pairs。
