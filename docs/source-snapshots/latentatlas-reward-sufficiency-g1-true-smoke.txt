## 8. Analysis

工程边界已成立：GPU 端仅持有 label-free bundle；SD、FLUX 和 DC-AE 完成真实 CUDA 编码；source-only labels 用于 scaler / MLP 训练和 validation；checkpoint 及 correct/wrong score 先封存；本地 target provider 对 exact 64-pair batch 只打开一次；oracle metrics 被纳入 terminal seal。独立审计从 sealed tensors / checkpoint / scores 精确重算两个条件，结果一致且无 Critical / Important findings；签名 review 也绑定了 exact run projection。

这次 `f6b737a` run 替代了旧 `c0cdba3.../b3114bf` candidate 作为当前权威 engineering record。旧 candidate 的 raw-Parquet 主机污染与 oracle 未进 terminal seal 问题是历史 incident，不再描述新 run。

科学上仍应保守：只有一个 Anchor seed、一个 training seed、三个 epochs 和 64 个 target pairs；而且 wrong control 的表现更好。需要独立 formal design 的多 seed、完整 baselines/controls 与统计 gate，才能评估稳定 reward transfer。

后续 formal G1 已在 commit `f342b9c` 上完成 terminal seal，正式 decision=`no`、subtype=`control_failure`。该结果还记录了独立科学审计 `Critical=0, Important=1` 的 shuffle-validation 真实标签选择通道；详见 [[latentatlas-reward-sufficiency-g1-formal]]。不得把本 smoke 的工程 `pass` 与 formal 科学 gate 混为一谈。

## 9. Problems

- 原始 `f6b737a` GPU run 在产物写入后因 `json.dumps` 处理嵌套 `mappingproxy` 而 shell exit `1`；这是保留的历史 post-write presentation bug。formal-authority successor `f342b9c` 已形成可审批的 clean engineering chain。
- Selected epoch=`3` 等于 max epoch=`3`，不能声称已收敛。
- Relation metadata 仍记录 `wall_seconds=0.0`，不能当作真实 relation-stage 耗时。
- 小样本 / 单 seed 下 wrong Anchor 更好的原因未定；可能来自抽样波动、未收敛、permutation 偶然对齐，或当前 relation/head 不依赖正确 anchor identity。
- Signed review gate 是后续 formal 权限链的一部分，不等于 formal experiment 已执行或通过。
